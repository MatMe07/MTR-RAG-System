# Контракт каталога для backend

## Основной набор

Для демонстрации используется
`data/catalog/regulated_mtr_catalog_1000.jsonl`. Каждая строка содержит
одну полную карточку ItemCardV2. Один и тот же набор загружается:

- в `mtr_items` как карточки МТР;
- в `ksm_items` как складские позиции КСМ;
- из `mtr_items` в Qdrant как поисковый индекс.

Файлы с правилами, графом и проверочными вопросами не нужно загружать в
Qdrant как изделия.

## Канонические свойства

Backend записывает в `properties JSONB` следующие единые ключи:

- `pn` - номинальное давление PN;
- `gost_tu` - основной ГОСТ или ТУ изделия;
- `h2s_confirmed` - подтверждение пригодности к H2S;
- `co2_confirmed` - подтверждение пригодности к CO2;
- `inner_coating` и `outer_coating` - наличие покрытий;
- `stock_qty` - синтетический складской остаток;
- геометрию, материал и дополнительные нормативные признаки.

Значение `null` означает, что характеристика не подтверждена. Оно не
равно `false`.

Старые ключи `pressure` и `gost_or_tu` поддерживаются только при чтении
и автоматически преобразуются в `pn` и `gost_tu`. Дополнительные поля
`standard`, `applicable_standards`, `required_evidence` и статусы
проверки сохраняются в JSONB и не мешают поиску.

## Загрузка

Перед загрузкой должен быть задан `DATABASE_URL` для PostgreSQL. Из
папки `backend`:

```powershell
python -m app.scripts.load_data_v2 `
  --catalog-jsonl ../data/catalog/regulated_mtr_catalog_1000.jsonl `
  --skip-sample
```

Команда повторно запускается безопасно: существующие строки с теми же
кодами МТР обновляются. PostgreSQL и JSON-каталог остаются основным
хранилищем карточек и складских свойств (векторная индексация в Qdrant
не входит в активный стек поиска).
