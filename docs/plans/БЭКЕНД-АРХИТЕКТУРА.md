## ЦЕЛЬ ЭТАПА

Создать детальный план бэкенд-архитектуры, который:

- Опирается на этапы 1–5 (парсинг, DAL, инструменты, оркестратор, ответ).
- Определяет структуру FastAPI-приложения (роутеры, сервисы, репозитории).
- Настраивает асинхронную обработку паспортов (Celery + Redis).
- Реализует миграции БД (Alembic).
- Внедряет логирование и обработку ошибок.
- Обеспечивает безопасность (JWT, роли, CORS).

## B.2. СЛОИ АРХИТЕКТУРЫ

### B.2.1 Роутеры (API-слой)

Ответственность: приём запросов, валидация входных данных, вызов сервисов, формирование HTTP-ответов.

Пример структуры для search.py:

```
POST /api/v1/search
  - Валидация: SearchRequest (pydantic)
  - Вызов: search_service.execute(request)
  - Ответ: SearchResponse (JSON из Этапа 5)

GET /api/v1/search/history
  - Требуется: аутентификация
  - Вызов: audit_service.get_user_history(user_id, limit)
  - Ответ: List[SearchHistoryEntry]
```

Общие правила:

- Каждый роутер использует зависимости для внедрения сервисов.
- Ответы строго типизированы через Pydantic.
- Обработка ошибок: try/except с кастомными исключениями → HTTP-коды.

### B.2.2 Сервисы (бизнес-логика)

Ответственность: координация провайдеров, инструментов, оркестратора и DAL.

| Сервис | Ответственность | Использует |
|---|---|---|
| SearchService | Оркестратор (Этап 4) + парсинг (Этап 1) | ParserPipeline, Orchestrator |
| PassportService | Загрузка, обработка (OCR + LLM), статус | PassportProvider, Celery |
| ComponentService | Получение детали с обогащением | DAL |
| CompareService | Сравнение двух деталей | DAL |
| NormsService | Поиск в ЛНД/ГОСТах | NormsProvider |
| ExpertService | Проверка запросов, связывание паспортов | ExpertProvider, DAL |
| AuditService | Логирование действий | AuditRepository |
| AdminService | CRUD для справочников, перезагрузка кеша | DictionaryRepository, CacheManager |
| AuthService | JWT, роли, регистрация | UserRepository |

Пример SearchService.execute():

```
1. Принять SearchRequest (query, mode, filters).
2. Вызвать ParserPipeline.parse(query) → ParsedRequest.
3. Вызвать Orchestrator.execute(parsed_request, mode) → AgentContext.
4. Вызвать ResponseBuilder.build(AgentContext) → JSON-ответ.
5. Вызвать AuditService.log(request_id, user_id, action, result).
6. Вернуть JSON-ответ.
```

### B.2.3 Репозитории (доступ к данным)

Ответственность: низкоуровневые операции с SQLAlchemy (CRUD, сложные запросы).

| MTRRepository | mtr_items, mtr_item_history |
| StockRepository | candidate_items |

Пример MTRRepository.get_by_ksm():

```

2. Если нет → вернуть None
3. Если есть → преобразовать в Pydantic-модель Component
```

## B.3. АСИНХРОННАЯ ОБРАБОТКА (CELERY)

### B.3.1 Назначение

Обработка паспортов (OCR, извлечение параметров, связывание с KSM) занимает 2–5 минут.
Эти задачи выполняются в фоновых воркерах, чтобы не блокировать API.

### B.3.2 Структура

```
Брокер: Redis (локально)
Воркеры: Celery (минимум 2 воркера)
```

### B.3.3 Задачи

| Задача | Вход | Выход | Действие |
|---|---|---|---|
| process_passport | document_id | status | 1. OCR (Tesseract/Doctr). 2. Извлечение таблиц. 3. Извлечение параметров (LLM + эвристики). 4. Сохранение в extracted_characteristics. 5. Вызов suggest_ksm_links. 6. Автоматическая связь при confidence > 0.8. 7. Установка флага needs_review при 0.6–0.8. |
| reprocess_passport | document_id | status | Переобработка (если изменились правила или LLM). |

### B.3.4 Мониторинг задач

```
GET /api/passport/status/{document_id}:
  - Если задача выполняется → статус "processing", прогресс (0–1)
  - Если завершена → статус "completed" или "error"
  - Если не найдена → статус "not_found"
```

### B.4.1 Настройка

```

### B.4.2 Стратегия миграций

| Миграция | Таблицы |
|---|---|
| 001_initial | Все таблицы из Этапа 2 (mtr_items, candidate_items, documents, logs, validation_rules, etc.) |
| 002_add_history | mtr_item_history |
| 003_add_audit | data_access_logs, tool_execution_logs |
| 004_add_dicts | group_keywords, contextual_overrides, synonyms, validation_constants |

Правила:

- Каждая миграция — отдельный файл в versions/.
- Миграции проверяются при старте через alembic upgrade head.
- При изменении схемы — создаётся новая миграция через alembic revision --autogenerate.

## B.5. ЛОГИРОВАНИЕ И ОБРАБОТКА ОШИБОК

### B.5.1 Логирование

Уровни: DEBUG, INFO, WARNING, ERROR, CRITICAL.
Формат: JSON (для ELK / Loki) + цветной вывод в консоль.

Где логируется:

| Место | Что логируется |
|---|---|
| Роутеры | Входящие запросы, параметры, ответы (без чувствительных данных) |
| Сервисы | Вызовы оркестратора, этапов, длительность |
| Репозитории | SQL-запросы (в DEBUG) |
| Провайдеры | Запросы к Neo4j, Qdrant, fallback-механизмы |
| Воркеры (Celery) | Статус задач, ошибки OCR/LLM |
| Аудит | Действия пользователей (кто, когда, что сделал) |

### B.5.2 Обработка ошибок

Кастомные исключения:

```
AppException (базовое):
  - code: str
  - message: str
  - details: dict (опционально)
  - http_status: int

NotFoundError (404) → AppException
ValidationError (422) → AppException
UnauthorizedError (401) → AppException
ForbiddenError (403) → AppException
ConflictError (409) → AppException
InternalError (500) → AppException
```

Хендлер в FastAPI:

```
@app.exception_handler(AppException)
def handle_app_exception(exc):
    return JSONResponse(
        status_code=exc.http_status,
        content={"code": exc.code, "message": exc.message, "details": exc.details}
    )
```

| Поле | Назначение |
|---|---|

| role | user / expert / auditor / admin |
| exp | Время жизни (24 часа) |

### B.6.2 Защита эндпоинтов

```
@router.post("/search")
async def search(
    request: SearchRequest,
    current_user: User = Depends(get_current_user)  # обязательная аутентификация
):
    ...

@router.get("/expert/reviews")
async def get_reviews(
    current_user: User = Depends(require_role("expert", "admin"))
):
    ...
```

Роли:

- user — может всё, кроме экспертных и административных действий.
- expert — может редактировать экспертные решения и связывать паспорта.
- auditor — может только просматривать логи.
- admin — может управлять справочниками и пользователями.

## B.8. ТЕСТИРОВАНИЕ (ИНТЕГРАЦИЯ)

### B.8.1 Интеграционные тесты

| Сценарий | Что проверяет |

```
