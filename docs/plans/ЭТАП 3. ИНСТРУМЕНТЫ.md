
## ЦЕЛЬ ЭТАПА 3

Создать набор специализированных инструментов, каждый из которых:

- Выполняет одну атомарную задачу (поиск, проверка склада, обход графа, анализ совместимости).
- Использует DAL (Этап 2) как единственный источник данных.
- Возвращает структурированный результат для оркестратора (Этап 4).
- Содержит валидацию входных данных, обработку ошибок и логирование.
- Не содержит логики планирования — только исполнение.

## 3A. СПИСОК ИНСТРУМЕНТОВ (13 ШТУК)

### 3A.1 search_catalog

Назначение: Поиск деталей в каталоге по параметрам.
Вход:
- params: SearchParams — параметры поиска.
- detail_level: str — basic, with_stock, full.

Выход: PaginatedResult[Component] или PaginatedResult[EnhancedSearchResult].
Использует DAL: dal.search_catalog().

Ограничения:
- При detail_level="full" обогащение (остатки, совместимость, соседи) выполняется только для первых 20 результатов.
- Остальные результаты возвращаются в формате basic.

Логика: Прямой вызов DAL с переданными параметрами.

### 3A.2 get_component

Назначение: Получение детали по идентификатору.

Вход:
- identifier: str — KSM, MTR или COMP-код.
- detail_level: str — basic, with_stock, full.

Выход: Component (при basic) или EnhancedSearchResult (при with_stock/full).
Использует DAL: dal.get_component().

Логика: При detail_level="full" подтягивает остаток, совместимость, соседей, параметры из паспорта.

### 3A.3 search_by_passport

Назначение: Поиск деталей по параметрам, извлечённым из паспорта.

Вход: document_id: str.
Выход: List[KsmSuggestion] — кандидаты с confidence.

Использует DAL:
- dal.get_passport_params(document_id) — извлечённые параметры.
- dal.search_catalog(params, detail_level="basic") — поиск по этим параметрам.

Логика:
1. Извлечь параметры из паспорта.
2. Для каждого параметра с confidence > 0.6 выполнить поиск в каталоге.
3. Агрегировать результаты по ksm_code.
4. Для каждого кандидата вычислить взвешенный confidence:

```
WEIGHTS = {
    "dn": 0.30,
    "pn": 0.25,
    "material": 0.20,
    "angle": 0.15,
    "medium": 0.10
}
```
confidence = sum(weight for each matched parameter) / sum(weights for all extracted parameters)

Веса хранятся в validation_constants и могут быть изменены экспертом.

5. Вернуть кандидатов, отсортированных по убыванию confidence.

Важно: Инструмент не связывает паспорт с KSM автоматически. Это выполняет PassportProvider.link_passport_to_ksm() при confidence > 0.8.

### 3A.4 check_stock

Назначение: Проверка остатка по одному или нескольким KSM.

Вход: ksm_codes: List[str].
Выход: Dict[str, StockItem].
Использует DAL: dal.get_stock_batch().

Особенности:
- Если список пуст — возвращает пустой словарь без вызова DAL.
- Если какой-то KSM не найден — в словаре отсутствует запись для него.

Логика: Прямой вызов DAL.

### 3A.5 get_low_stock_items

Назначение: Получение деталей с остатком ниже порога.

Вход:
- threshold: float = 2.0 — порог остатка.
- unit_code: str (опционально) — код участка.
Выход: List[StockItem].

Использует DAL:
- Если unit_code указан:
  - dal.get_unit_structure(unit_code, limit=999) — все компоненты участка.
  - dal.get_stock_batch(ksm_codes) — остатки для них.
  - Отфильтровать по quantity < threshold.
- Если unit_code не указан:
  - dal.get_low_stock_items(threshold).

Логика: Прямой вызов DAL с дополнительной фильтрацией по участку.

### 3A.6 get_unused_stock
Назначение: Получение деталей с большим остатком, не установленных ни на одном участке.

Вход: min_qty: float = 50.
Выход: List[StockItem].

Использует DAL:
- dal.get_uninstalled_components() — список KSM без установки.
- dal.get_stock_batch(ksm_codes) — остатки для них.
- Отфильтровать по quantity > min_qty.

Логика: Комбинирует данные из графа и склада.

### 3A.7 get_unit_structure

Назначение: Получение структуры участка с пагинацией.

Вход:
- unit_code: str.
- limit: int = 20.
- offset: int = 0.
Выход: PaginatedResult[EnhancedSearchResult].

Использует DAL:
- dal.get_unit_inventory(unit_code) — полная структура.
- Применить пагинацию к списку компонентов.

Логика: DAL возвращает UnitInventory со всеми компонентами. Инструмент применяет пагинацию к полю components и возвращает PaginatedResult.

Ограничение: При limit > 100 автоматически ограничивается до 100.

### 3A.8 get_neighbors

Назначение: Получение соседних компонентов для заданной детали.

Вход:
- ksm_code: str.
- depth: int = 1 (1–5).
- direction: str = "both" (upstream, downstream, both).
Выход: List[NeighborInfo].

Использует DAL: dal.get_neighbors().

Ограничения:
- depth не более 5 (проверяется в валидации).
- При depth > 5 — ошибка INVALID_PARAMS.

Логика: Прямой вызов DAL.

### 3A.9 is_installed_anywhere

Назначение: Проверка, установлена ли деталь на каком-либо участке.

Вход: ksm_code: str.
Выход: bool.

Использует DAL: dal.is_installed_anywhere().

Логика: Прямой вызов DAL.

### 3A.10 check_compatibility

Назначение: Проверка совместимости детали с условиями эксплуатации.

Вход:
- ksm_code: str.
- context: CompatibilityContext.
Выход: CompatibilityResult.

Использует DAL:
- dal.get_component(ksm_code).
- dal.check_compatibility(component, context).

Логика: Если деталь не найдена — ошибка NOT_FOUND.

### 3A.11 check_compatibility_batch

Назначение: Проверка совместимости для списка деталей.

Вход:
- ksm_codes: List[str].
- context: CompatibilityContext.
Выход: Dict[str, CompatibilityResult].

Использует DAL:
- Для каждого кода — dal.get_component() (можно batch-запросом, если DAL поддерживает).
- dal.check_compatibility_batch(components, context).

Ограничения:
- Максимальный размер списка — 50.
- При превышении — ошибка BATCH_TOO_LARGE с указанием максимального размера.

Логика: Оптимизирует количество запросов к БД.

### 3A.12 search_norms

Назначение: Поиск в нормативной базе (ЛНД, ГОСТы, ТУ).

Вход:
- query: str.
- limit: int = 5.
- document_type: str (опционально) — фильтр по типу документа (ЛНД, ГОСТ, ТУ).
Выход: List[NormFragment].

Использует DAL: dal.search_norms(query, limit).

Особенности:
- Если document_type указан — DAL фильтрует результаты по этому полю (через Qdrant filter или PostgreSQL).
- Если document_type не указан — возвращаются все типы.

Логика: Прямой вызов DAL.

### 3A.13 get_component_history

Назначение: Получение истории изменений атрибутов детали.

Вход:
- ksm_code: str.
- limit: int = 10.
- offset: int = 0.
Выход: PaginatedResult[ComponentHistory].

Использует DAL: dal.get_component_history(ksm_code, limit, offset).

Логика: Прямой вызов DAL.

## 3C. ВАЛИДАЦИЯ ВХОДНЫХ ДАННЫХ

Каждый инструмент перед вызовом проверяет входные данные по JSON Schema.

Пример для search_catalog:
```
input_schema = {
  "type": "object",
  "properties": {
    "params": {
      "type": "object",
      "properties": {
        "item_type": {"type": "string"},
        "dn": {"type": "integer", "minimum": 10, "maximum": 2000},
        "pn": {"type": "number", "minimum": 0.1},
        "limit": {"type": "integer", "minimum": 1, "maximum": 100}
      }
    },
    "detail_level": {"type": "string", "enum": ["basic", "with_stock", "full"]}
  },
  "required": ["params"]
}
```

Общие правила валидации:
- depth в get_neighbors — от 1 до 5.
- limit во всех методах с пагинацией — не более 100.
- ksm_codes в check_compatibility_batch — не более 50.
- ksm_codes в check_stock — если пусто, возвращается пустой словарь без ошибки.

При ошибке валидации инструмент возвращает ToolError с кодом INVALID_PARAMS.

## 3D. ОБРАБОТКА ОШИБОК

Каждый инструмент возвращает структурированную ошибку:
```
ToolError:
  - code: str               # NOT_FOUND, INVALID_PARAMS, DAL_ERROR, TIMEOUT, BATCH_TOO_LARGE
  - message: str
  - details: dict (опционально)
```

Примеры:
```
{"code": "INVALID_PARAMS", "message": "Параметр 'dn' должен быть целым числом от 10 до 2000", "details": {"received": 2500, "max": 2000}}
{"code": "BATCH_TOO_LARGE", "message": "Слишком много деталей. Максимум 50", "details": {"received": 100, "max": 50}}
{"code": "NOT_FOUND", "message": "Деталь с KSM-SYN-REG-000999 не найдена"}
```

Оркестратор (Этап 4) получает ошибку и решает: задать уточняющий вопрос, попробовать другой инструмент или завершить работу.

## 3F. ЛОГИРОВАНИЕ ВЫЗОВОВ

Каждый вызов инструмента логируется в таблицу tool_execution_logs:
- request_id: UUID
- tool_name: str
- input: dict
- output: dict (или error)
- duration_ms: int
- user_id: str (опционально)
- created_at: timestamp

Хранилище: PostgreSQL.

Индексы: по request_id, tool_name, created_at.
