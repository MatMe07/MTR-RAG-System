## ЦЕЛЬ

Создать унифицированный слой доступа ко всем источникам данных, который:

- Абстрагирует агента от физического хранения (PostgreSQL, Neo4j, Qdrant).
- Предоставляет единые интерфейсы для всех операций.
- Обеспечивает выбор уровня детализации ответа (basic / with_stock / full).
- Гарантирует согласованность данных (PostgreSQL — единственный источник истины для атрибутов).
- Поддерживает асинхронную обработку паспортов с чёткими порогами автоматической связки.

## 2B. ПРОВАЙДЕРЫ ДАННЫХ

### 2B.1 CatalogProvider

Ответственность: работа с каталогом МТР.

Методы:

| Метод | Вход | Выход |
|---|---|---|
| async get_component(identifier) | str | Component или None |
| async search_by_params(params) | SearchParams | PaginatedResult[Component] |
| async get_all_types() | - | List[str] |
| async get_all_materials() | - | List[str] |
| async get_all_gost_tu() | - | List[str] |
| async get_component_history(ksm_code, limit, offset) | str, int, int | PaginatedResult[ComponentHistory] |

Источник: PostgreSQL, таблица mtr_items и mtr_item_history.

Логика определения идентификатора:

- KSM-* → поиск по ksm_code
- MTR-* → поиск по mtr_code
- COMP-* → поиск в таблице components (маппинг component_id → ksm_code)
- иначе → поиск по обоим полям

### 2B.2 StockProvider

### 2B.3 GraphProvider

Ответственность: работа с топологией участков.

Особенность: Neo4j хранит только ksm_code и item_type. Все атрибуты — из PostgreSQL.

Источники:

- Основной: Neo4j.
- Резервный: PostgreSQL, таблица pipeline_edges.

### 2B.4 PassportProvider

Ответственность: извлечение параметров из паспортов, управление документами и связка с KSM.

Особенность: провайдер не выполняет поиск по каталогу — только извлечение и предложение кандидатов.

Методы:

| Метод | Вход | Выход |
|---|---|---|
| async extract_params(document_id) | str | Dict[str, ExtractedParam] |
| async get_extracted_params(document_id) | str | Dict[str, ExtractedParam] |
| async get_document_metadata(document_id) | str | DocumentMetadata |
| async get_passport_text(document_id, page) | str, int | str |
| async link_passport_to_ksm(document_id, ksm_code, confidence) | str, str, float | bool |
| async suggest_ksm_links(document_id) | str | List[KsmSuggestion] |
| async get_processing_status(document_id) | str | str |

Источник: PostgreSQL, таблицы documents, extracted_characteristics, document_links.

Пороги автоматической связки (хранятся в validation_constants):

- confidence > 0.8 → автоматическая связь
- 0.6 <= confidence <= 0.8 → флаг needs_review
- confidence < 0.6 → без связки

### 2B.5 NormsProvider

Ответственность: проверка нормативных требований и поиск в документации.

Методы:

| Метод | Вход | Выход |
|---|---|---|
| async check_compatibility(component, context) | Component, CompatibilityContext | CompatibilityResult |
| async check_compatibility_batch(components, context) | List[Component], CompatibilityContext | Dict[str, CompatibilityResult] |
| async search_norms(query, limit) | str, int | List[NormFragment] |
| async get_norm_by_id(norm_id) | str | NormDocument |
| async get_norm_fragment(norm_id, section) | str, str | str |

Источники:

- Жёсткие правила: PostgreSQL, таблица compatibility_rules.
- Векторный поиск: Qdrant, коллекция norm_documents.
- Метаданные: PostgreSQL, таблица norm_documents.

Логика check_compatibility():

1. По материалу компонента ищет правила в compatibility_rules с фильтром по medium.
2. Фильтрует по PN, температуре, климату.
3. Если найдено правило с compatible = false → возвращает запрет с предупреждением.
4. Если правило требует покрытия, а у компонента его нет → запрет с действием.
5. Если правил нет → разрешение с предупреждением "Нет нормативных данных".

## 2C. DATA ACCESS LAYER

Ответственность: единая точка входа для агента.

Все методы асинхронные.

| Метод | Вход | Выход | Уровень детализации |
|---|---|---|---|
| async search_catalog(params, detail_level) | SearchParams, str | PaginatedResult[Component] | basic / with_stock / full |
| async get_component(identifier, detail_level) | str, str | Component или EnhancedSearchResult | basic / with_stock / full |
| async get_unit_inventory(unit_code) | str | UnitInventory | full (всегда) |
| async get_full_component_info(identifier) | str | EnhancedSearchResult | full (всегда) |
| async get_neighbors(ksm_code, depth) | str, int | List[NeighborInfo] | - |
| async check_compatibility(component, context) | Component, CompatibilityContext | CompatibilityResult | - |
| async search_norms(query) | str | List[NormFragment] | - |
| async extract_passport(document_id) | str | str (status) | - |
| async get_passport_status(document_id) | str | str | - |
| async get_passport_params(document_id) | str | Dict[str, ExtractedParam] | - |
| async get_component_history(ksm_code, limit, offset) | str, int, int | PaginatedResult[ComponentHistory] | - |

### 2C.1 Логика search_catalog(detail_level)

1. Выполнить поиск в CatalogProvider.search_by_params().
2. Если detail_level == "basic":
   - Вернуть результаты как есть (Component с match_score).
3. Если detail_level == "with_stock":
   - Взять первые 50 результатов.
   - Запросить остатки для них через StockProvider.get_stock_batch().
   - Обогатить каждый Component полем stock.
   - Вернуть PaginatedResult[Component] (stock — в attributes).
4. Если detail_level == "full":
   - Взять первые 20 результатов.
   - Для каждого:
     a. Получить остаток (StockProvider).
     b. Получить совместимость (NormsProvider).
     c. Получить соседей (GraphProvider, depth=1).
   - Вернуть EnhancedSearchResult для первых 20.
   - Остальные результаты (если есть) вернуть без обогащения.

### 2C.2 Логика extract_passport()

1. Сохранить документ в БД со статусом "pending".
2. Отправить задачу в очередь (Celery / RQ):
   a. Выполнить OCR (если необходимо).
   b. Извлечь текст и таблицы.
   c. Извлечь параметры (LLM + эвристики).
   d. Сохранить параметры в extracted_characteristics.
   e. Вызвать suggest_ksm_links().
   f. Если максимальный confidence > 0.8 → автоматическая связь.
   g. Если 0.6 <= confidence <= 0.8 → установить флаг needs_review.
   h. Если confidence < 0.6 → оставить без связки.
   i. Обновить статус документа на "completed" (или "error").
3. Вернуть document_id.

### 2C.3 Логика get_unit_inventory()

1. Получить все компоненты участка → GraphProvider.get_unit_structure().
2. Собрать все ksm_code.
3. Получить остатки → StockProvider.get_stock_batch().
4. Получить совместимость → NormsProvider.check_compatibility_batch().
5. Для каждого компонента собрать EnhancedSearchResult.
6. Сформировать UnitInventory со статистикой:
   - total_components
   - h2s_compatible
   - out_of_stock (stock_qty = 0)
   - low_stock (stock_qty < 2)

## 2E. ИМПОРТ ДАННЫХ

### 2E.1 Импорт MTR-каталога

Источник: CSV / Excel.

Действия:

1. Валидация структуры (обязательные поля: ksm_code, item_type).
2. Для каждой записи:
   - Если ksm_code существует → сохранить старые attributes в mtr_item_history, обновить запись.
   - Если не существует → создать новую.
3. Обновить attributes_schema_version (если структура JSONB изменилась).
4. Пересчитать эмбеддинги для Qdrant.
5. Инвалидировать кеш.

### 2E.2 Импорт складских остатков

Источник: Excel.

Действия:

1. Обновить candidate_items.
2. Инвалидировать stock:*.

### 2E.3 Импорт графа

Источник: JSON.

Действия:

1. Загрузить рёбра в Neo4j.
2. Загрузить рёбра в pipeline_edges (PostgreSQL).
3. Создать узлы Unit.
4. Инвалидировать graph:*.

### 2E.4 Импорт паспортов

Источник: PDF.

Действия:

1. Сохранить документ в documents со статусом pending.
2. Отправить в очередь на асинхронную обработку (см. 2C.2).
3. Пользователь получает document_id для отслеживания статуса.

### 2E.5 Импорт нормативных документов

Источник: PDF / текст.

Действия:

1. Извлечь текст (OCR при необходимости).
2. Разбить на разделы.
3. Сохранить метаданные в norm_documents.
4. Сохранить правила в compatibility_rules.
5. Сгенерировать эмбеддинги и загрузить в Qdrant.
6. Инвалидировать norms:*.

### 2E.6 Миграции JSONB-схемы

Механизм:

- В таблице mtr_items присутствует поле attributes_schema_version INT DEFAULT 1.
- При изменении структуры attributes создаётся скрипт миграции, который:
  - Обходит все записи.
  - Преобразует attributes к новой структуре.
  - Увеличивает attributes_schema_version.
  - Сохраняет изменения в mtr_item_history.

Проверка при старте системы:

- Система сравнивает текущую версию схемы с ожидаемой.
- Если версии не совпадают — система не запускается и выдаёт сообщение о необходимости запуска миграций.

### 2F.3 Процедура добавления документа


1. Разбить текст на логические фрагменты.
2. Для каждого фрагмента:
   a. Сгенерировать эмбеддинг.
   b. Сохранить метаданные в PostgreSQL.
   c. Отправить вектор + payload в Qdrant.
3. При недоступности Qdrant — использовать только PostgreSQL.


### 2F.4 Процедура поиска

1. Сгенерировать эмбеддинг запроса.
2. Выполнить поиск в Qdrant (Top-N).
3. При недоступности Qdrant — выполнить полнотекстовый поиск в PostgreSQL.
4. Вернуть фрагменты с метаданными.

## 2G. FALLBACK-МЕХАНИЗМЫ

| Источник | Основной | Резервный | Поведение при отказе |
|---|---|---|---|
| PostgreSQL (каталог) | PostgreSQL | JSON-бекап | Чтение из JSON (только чтение). При отсутствии — ошибка. |
| PostgreSQL (склад) | PostgreSQL | In-memory кеш | Использовать последнюю выгрузку. При отсутствии — ошибка. |
| Neo4j (граф) | Neo4j | PostgreSQL (pipeline_edges) | Медленнее, но работает. |
| Qdrant (нормы) | Qdrant | PostgreSQL (полнотекстовый) | LIKE-поиск. |
| Qdrant (каталог) | Qdrant | PostgreSQL (JSONB-фильтр) | Фильтрация по attributes. |

Логирование: при переключении на резервный источник в data_access_logs фиксируется причина.

## 2H. ЛОГИРОВАНИЕ

### 2H.1 Что логируется

- Время запроса.
- Метод DAL и параметры.
- Использованный провайдер.
- Время выполнения (мс).
- Наличие кеша (hit/miss).
- Использование fallback (да/нет, причина).
- Ошибки.

### 2H.2 Хранилище

PostgreSQL, таблица data_access_logs.

Дублирование в JSON-файлы для аудита (по требованию ИБ).

### 2H.3 Структура таблицы

```sql
CREATE TABLE data_access_logs (
    id BIGSERIAL PRIMARY KEY,
    request_id UUID NOT NULL,
    method_name TEXT NOT NULL,
    params JSONB,
    provider_used TEXT,
    duration_ms INT,
    cache_hit BOOLEAN,
    fallback_used BOOLEAN,
    fallback_reason TEXT,
    error TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_dal_request ON data_access_logs(request_id);
CREATE INDEX idx_dal_created ON data_access_logs(created_at);
```
