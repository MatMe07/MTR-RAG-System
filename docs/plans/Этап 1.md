# 1A. КЛАССИФИКАЦИЯ ГРУПП (ПЕРВЫЙ ШАГ)

## 1A.1 Базовые словари ключевых слов

Составить словарь ключевых слов для 7 групп:

ПОИСК: найди, покажи, подбери, какой, вариант, подходящий, код, артикул, номер

СКЛАД: склад, остаток, наличие, сколько, есть в наличии, отсутствует, нет, запас

РЕМОНТ: сломался, ремонт, замена, отказал, повреждён, авария, поломка

ЗАМЕНА: замени, аналог, вместо, подбери замену, замена на, взаимозаменяем

АНАЛИЗ: изменится, последствия, влияние, что будет, риск, опасность, проверить

ОБЪЯСНЕНИЕ: объясни, расскажи, что значит, чем отличается, опиши, расшифруй

ДОКУМЕНТЫ: паспорт, ГОСТ, ТУ, ЛНД, документы, сертификат, разрешение

## 1A.2 Контекстные правила переопределения (НОВОЕ)

Реализовать приоритетные контекстные паттерны, которые переопределяют базовую классификацию:

| Контекстный паттерн | Итоговая группа | Пример |
|---|---|---|
| "подбери" + "замену" | ЗАМЕНА | "Подбери замену задвижке" |
| "замена" + "DN... на DN..." | ЗАМЕНА | "Замена DN150 на DN200" |
| "расскажи" + ("паспорт" или "ГОСТ") | ДОКУМЕНТЫ | "Расскажи, что в паспорте" |
| "найди" + ("паспорт" или "ГОСТ") | ДОКУМЕНТЫ | "Найди паспорт для COMP-SYN-010" |
| отрицание "нет" в начале или как отрицание | Игнорировать | "Нет, это не подходит" → не СКЛАД |
| "сломался" + "замени" | РЕМОНТ (приоритет выше ЗАМЕНЫ) | "Сломался отвод, замени его" |

## 1A.3 Rule-based классификатор

Реализовать классификатор:

- Точное совпадение ключевых слов (регистронезависимо)
- Подсчёт совпадений по каждой группе
- Применение контекстных правил (переопределение)
- Выход: список групп с количеством совпадений и confidence

## 1A.4 ML fallback-классификатор

Реализовать fallback (если rule-based confidence < 0.5):

- Использовать fastText или DistilBERT (7 классов)
- Обучить на 500+ размеченных запросах
- Выход: список групп с вероятностью

## 1A.5 Комбинированный классификатор

Реализовать комбинирование:

- Если rule-based дал группу с confidence > 0.7 — берём её
- Если rule-based дал несколько групп с равным весом — используем ML fallback
- Если ML fallback не уверен (< 0.5) — переводим в UNCLEAR

## 1A.6 Детектор пустого/некорректного запроса

- Если запрос короче 3 слов ИЛИ не содержит ни одного ключевого слова → статус UNCLEAR
- Перевести в диалоговый режим: "Уточните, что вы ищете: деталь, склад, ремонт или документы?"

# 1B. ДЕТЕКЦИЯ АТОМАРНЫХ ИНТЕНТОВ (28 ШТУК)

## 1B.1 Группа ПОИСК (4 интента)

- FIND_BY_CODE: если есть MTR-XXX или KSM-XXX (regex)
- FIND_BY_COMPONENT: если есть COMP-SYN-XXX (regex)
- FIND_BY_PARAMS: если есть item_type + (DN или материал) → дефолтный
- COMPARE_DUPLICATES: если есть "одинаковые", "дубли", "разные коды", "несколько КСМ"

## 1B.2 Группа СКЛАД (4 интента)

- CHECK_STOCK: если есть ksm_code или item_type + dn → дефолтный
- CHECK_MINIMUM_STOCK: если есть "по две штуки", "минимум", "хватает ли", "достаточно"
- LIST_OUT_OF_STOCK: если есть "нет на складе", "отсутствует", "не хватает"
- FIND_UNUSED_STOCK: если есть "остаток >", "больше 50", "избыток", "не установлены", "не используются"

## 1B.3 Группа РЕМОНТ (2 интента)

- PLAN_REPAIR: если есть component_id + "сломался/ремонт/замена" → дефолтный
- BUILD_REPAIR_KIT: если есть "комплект", "собери", "список деталей", "подготовь"
- REPAIR_WITH_CHECKS: component_id или unit_id, medium

## 1B.4 Группа ЗАМЕНА (4 интента) (ОБНОВЛЕНО)

- FIND_ALTERNATIVE: если есть "найди аналог", "подбери замену" → дефолтный
- REPLACE_WITH_COMPOSITE: если есть "2 отвода 45 вместо 1 отвода 90" или "составная замена"
- REPLACE_WITH_DIFFERENT_SIZE: если есть "замени DN... на DN...", "вместо DN... поставить DN..." (НОВОЕ)
- COMPARE_ALTERNATIVES: если есть "сравни", "с объяснением", "отличия"

## 1B.5 Группа АНАЛИЗ (5 интентов)

- IMPACT_MEDIUM_CHANGE: если есть "смена среды", "перевод на H2S/CO2"
- IMPACT_DIAMETER_CHANGE: если есть "заменить DN... на DN..."
- IMPACT_MATERIAL_CHANGE: если есть "заменить сталь ... на ..."
- IMPACT_PRESSURE_CHANGE: если есть "заменить PN... на PN..."
- ANALYZE_RISK: если есть "риск", "опасность", "самый высокий риск"

## 1B.6 Группа ОБЪЯСНЕНИЕ (2 интента)

- EXPLAIN_TERM: если есть "что значит", "объясни", "расскажи про" → один термин
- EXPLAIN_DIFFERENCE: если есть "чем отличается" → два термина

## 1B.7 Группа ДОКУМЕНТЫ (3 интента)

- FIND_DOCUMENTS: если есть "паспорт", "документы" → дефолтный
- FIND_STANDARDS: если есть "ГОСТ", "ТУ", "норматив"
- GET_UNIT_STRUCTURE: если есть "из чего состоит", "состав участка", "схема"

## 1B.8 Определение главного интента (НОВОЕ)

Реализовать ранжирование по степени явности:

- Если есть явный глагол действия ("замени", "найди", "отремонтируй") — он главный
- Если есть только ключевые слова без явного глагола — использовать приоритеты (вторично)
- Выход: список интентов с пометкой is_primary: true/false

## 1B.9 Приоритеты внутри группы

Для каждой группы определить порядок приоритета:

ПОИСК: FIND_BY_CODE > FIND_BY_COMPONENT > FIND_BY_PARAMS > COMPARE_DUPLICATES

СКЛАД: CHECK_STOCK > CHECK_MINIMUM_STOCK > LIST_OUT_OF_STOCK > FIND_UNUSED_STOCK

РЕМОНТ: PLAN_REPAIR > BUILD_REPAIR_KIT

ЗАМЕНА: FIND_ALTERNATIVE > REPLACE_WITH_DIFFERENT_SIZE > REPLACE_WITH_COMPOSITE > COMPARE_ALTERNATIVES

АНАЛИЗ: все равны (зависят от параметров)

ОБЪЯСНЕНИЕ: EXPLAIN_TERM > EXPLAIN_DIFFERENCE

ДОКУМЕНТЫ: FIND_DOCUMENTS > FIND_STANDARDS > GET_UNIT_STRUCTURE

# 1D. ЦЕНТРАЛЬНЫЙ ПАРАМЕТР EXTRACTOR

## 1D.1 Общая структура

Создать класс ParameterExtractor с методом extract_all(text) -> dict

Вызывать все специализированные парсеры последовательно

Возвращать единый словарь параметров

## 1D.2 Парсер геометрии

- DN: `DN\s*(\d{2,4})`, `Ду\s*(\d{2,4})`, `(\d{2,4})\s*мм`
- Угол: `(\d{2,3})\s*град`, `(\d{2,3})°`
- Толщина стенки: `(\d{1,2})x(\d{1,2})`, `стенка\s*(\d{1,2})`
- Диаметры для переходов: `с (\d{2,4}) на (\d{2,4})`

## 1D.3 Парсер давления

- `PN\s*(\d{2,4})`, `Ру\s*(\d{2,4})`
- `(\d{2,4})\s*МПа`, `(\d{2,4})\s*кгс/см2`, `(\d{2,4})\s*бар`
- Нормализация: бар → МПа (делить на 10), кгс/см2 → МПа (делить на 10)

## 1D.4 Парсер материала

- Словарь марок стали: 09Г2С, 13ХФА, Сталь20, 09ГСФ, 12Х18Н10Т, 15Х5М
- Класс прочности: К42, К48, К52, К55, К60

## 1D.5 Парсер среды

- H2S, сероводород, кислая среда, CO2, углекислый газ, нефть, газ, вода, пар
- Нормализация: H2S → h2s_confirmed: true

## 1D.6 Парсер климатики

- У, ХЛ, УХЛ, Т (по ГОСТ 15150)

## 1D.7 Парсер идентификаторов

- MTR-SYN-REG-\d{6}, KSM-SYN-REG-\d{6}
- COMP-SYN-\d{3}, UNIT-SYN-[A-Z0-9-]+

## 1D.8 Парсер типа изделия

- Словарь: труба, задвижка, отвод, переход, тройник, заглушка, кран, фланец
- Синонимы: задвижка = клин, отвод = колено, переход = редукция

## 1D.9 Парсер ГОСТ/ТУ

- ГОСТ\s*\d{4}-\d{4}, ТУ\s*\d{4}-\d{3}-\d{8}-\d{4}
- Извлекать как gost_tu в сыром виде

## 1D.10 Парсер условных обозначений (из ТЗ раздел 6.2)

- Пример: "Отвод П90-219х8-09Г2С-ХЛ ГОСТ 17375"
- Разбить на: тип, угол, DN, толщина, материал, климатика, ГОСТ
