# Полнота каталога из 1000 позиций

## Итог

Каталог достаточен для базового MVP поиска по шести классам изделий, но
пока недостаточен для полного комплектования ремонта.

| Класс | Количество |
|---|---:|
| Труба | 220 |
| Отвод | 220 |
| Переход | 150 |
| Задвижка | 150 |
| Заглушка | 130 |
| Тройник | 130 |
| **Всего** | **1000** |

Все 1000 карточек содержат `pn`, марку стали, среду, `gost_tu`,
складской остаток и отдельные поля подтверждения H2S и CO2.

## Что отсутствует

В согласованных вопросах про план ремонта нужны классы, которых нет в
каталоге:

- фланцы;
- прокладки;
- крепеж;
- сварочные материалы;
- материалы для восстановления покрытия.

Пока эти классы не добавлены, система должна перечислять их как
необходимые, но явно сообщать, что позиции и остатки не найдены в
каталоге. Придумывать коды КСМ запрещено.

## Качество данных

- 12 позиций имеют нулевой остаток и подходят для проверки складских
  сценариев.
- У всех 1000 позиций пригодность к H2S и CO2 имеет значение `null`.
  Это намеренно: синтетическое упоминание среды не считается паспортным
  подтверждением.
- Найдена одна пара с одинаковой нормализованной сигнатурой:
  `KSM-SYN-REG-000753` и `KSM-SYN-REG-000773`. Обе записи описывают
  заглушку 76x4 из стали 20. Их можно использовать для проверки поиска
  возможных дублей, но удалять автоматически нельзя.

## Рекомендация

До демонстрации обычного поиска расширять каталог не обязательно.
Сначала нужно проверить поиск, правила и остатки на текущих 1000
позициях.

Перед демонстрацией полного плана ремонта стоит добавить отдельный
синтетический набор соединительных и ремонтных материалов. Его лучше
согласовать с Никитой, потому что для этих классов понадобятся собственные
обязательные параметры и нормативы.

Повторный аудит запускается из папки `backend`:

```powershell
python -m app.scripts.audit_catalog_completeness
```
